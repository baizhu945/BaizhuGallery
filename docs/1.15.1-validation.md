# Gallery 1.15.1: fixes and regression scope

## Causes and fixes

- **Progress after minimizing:** the old progress display existed only as a dialog in the owner Activity window. Hiding that window could hide the only feedback even while the batch continued. The new dialog detaches when its Activity stops and redraws the live snapshot on return, unless explicitly dismissed or a confirmation is open. A separate, silent notification shows the real phase and counts while the window is minimized, if Android notifications are allowed. Enable it under **Settings → File operations → Batch progress notifications**. It contains no file names or thumbnails, is hidden on the lock screen, and is removed at the end. This is not a foreground service or a promise of continuation after process death. **Hide progress** still does not cancel work.
- **Hidden only after large batches:** entering Hidden only set the global temporary Show hidden flag, but leaving it cleared only the filter. A fresh load could therefore still show hidden rows. The filter now owns a scoped temporary grant that is revoked on exit. Explicit persistent/temporary Show hidden choices are independent. Folder and media loaders keep the original request identity through publication; verified bulk changes invalidate prepared snapshots. Existing authorization and hidden ownership rules are unchanged.

## Before the version bump

On a dedicated API 35 AVD, the published 1.15.0 APK (`378755d638a4bd0c3df113b4d6a5f150cb16c45ac6744f5e76d625f25b6e5cc0`) reproduced the stuck list after hiding 300 photos. Two visible anchor photos confirmed the discrepancy. A second batch continued after Home hid the dialog. Device hashes were measured on-device or by comparing the pulled APK; an earlier stream-based hash in the baseline notes was not reliable.

The signed pre-version candidate (`aef0c8b89e0e7252ca77c2ac327401603610d734ae93ddf3d399641fa4c50a16`, still version 1.15.0) passed:

- Hidden only ON/OFF in the same album, including fast repeated switching, and in Folders and All Photos with a separate all-hidden album. Pager return preserved the filter. Explicit temporary reveal stayed active until explicitly stopped.
- An actual 300-item unhide continued after Home with a real progress notification. Returning through Recents restored the dialog on the same Activity at 169/300, zero failed. The notification cleared on completion. With Android notifications blocked, no notification was posted; choosing Hide progress dismissed only the dialog.
- All 302 audited paths and SHA-256 values matched the expected filenames and contents before, after unhide, and after hiding again.
- Debug and signed Release builds, lint, detekt, the 64 hidden-policy tests, scoped-grant and stale-request tests, 25 filesystem tests, 16 progress-display checks, helper/index runner, 24 CI guards, Commons self-test and workflow lint. Gradle's inherited JUnit task is `NO-SOURCE`; those tests are standalone, not counted as JUnit coverage.

## Scope and limits

The version was changed only after these checks passed. The final 1.15.1 APK (`9ca6bdea62e137c3c1019c76982df20d5f3ce5cd1d1bda284b659900e03983b8`, version code **50**) uses the same application ID and release certificate as independent 1.15.0. The final build and static checks passed. An in-place install over the pre-version candidate, which had itself updated the published 1.15.0, preserved all 304 fixture paths and hashes across two albums. Launch and Hidden only ON/OFF passed; the short final smoke did not run a new batch. The temporary API 35 AVD was shut down afterward. No retag of 1.15.0, SDK/dependency changes, permission additions, Room changes or baseline edits were needed.

Testing used standard Android Home/Recents, not a MagicOS device. Vendor floating-window behavior, process destruction, and conflict/indeterminate notification rendering were not certified by the device run. Indeterminate behavior is covered by the pure state checks. No new whole-app performance measurements are claimed. The two previously stopped AVDs were not restarted.
